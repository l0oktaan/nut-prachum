# Set up a meeting นัดประชุม — หาวันที่ทุกคนว่างตรงกัน

เว็บแอปสำหรับนัดประชุม: ผู้จัด (เลขานุการหรือใครก็ได้) สร้างห้อง แตะเลือกวันที่บนปฏิทิน (แสดงปี พ.ศ.) แล้วส่งลิงก์ให้สมาชิก
สมาชิกเลือกวันเวลาที่ตัวเองสะดวก ระบบสรุปช่วงที่ว่างตรงกันมากที่สุดให้ **ไม่ต้องสมัครสมาชิก ไม่ต้องล็อกอิน**
แต่ยังรู้ได้ว่าใครเข้ามาแล้ว ใครตอบแล้ว และใครยังไม่ตอบ

**Stack:** Next.js 16 (App Router — ทั้ง frontend และ API) · PostgreSQL 17 · Tailwind CSS 4 · Docker Compose

## เริ่มใช้งาน

```bash
cp .env.example .env        # แก้ POSTGRES_PASSWORD
docker compose up -d --build
# เปิด http://localhost:3000
```

ตารางในฐานข้อมูลถูกสร้างอัตโนมัติตอนแอปเริ่มทำงาน ([src/instrumentation.ts](src/instrumentation.ts))

### พัฒนาบนเครื่อง

```bash
docker compose up -d db
cp .env.example .env.local  # ใช้ DATABASE_URL ที่ชี้ไป localhost
npm install
npm run dev
```

## การทำงาน (User flow)

```
ผู้จัด                          ระบบ                                สมาชิก
──────                          ────                                ──────
กรอกหัวข้อ, แตะเลือกวัน, ──▶  สร้างห้อง + admin key
รายชื่อสมาชิก (ไม่บังคับ)      ◀── ลิงก์ผู้ดูแล /r/{slug}/admin#key=…
                                    ลิงก์สมาชิก  /r/{slug}
ส่งลิงก์สมาชิกในกลุ่ม LINE ───────────────────────────────────▶  เปิดลิงก์
                                                                    “คุณคือใคร?” → เลือกชื่อ / พิมพ์ชื่อ
                                ออก token ส่วนตัว → cookie  ──▶   ระบบจำไว้บนอุปกรณ์นี้
                                                                    ลากเลือกช่อง สะดวก / ถ้าจำเป็น
                                บันทึกอัตโนมัติ ◀──────────────────
ดูสถานะรายคน + heatmap  ◀──   รวมผล, จัดอันดับช่วงที่ดีที่สุด
กด “ยืนยันเป็นวันประชุม” ──▶  แสดงแบนเนอร์สรุปวันให้ทุกคน   ──▶  เพิ่มลง Google Calendar / .ics
```

## การระบุตัวตนโดยไม่ต้องล็อกอิน

| ใคร | ยืนยันตัวตนด้วย | หมายเหตุ |
|---|---|---|
| ผู้จัด | **admin key** ใน `#hash` ของลิงก์ผู้ดูแล | อยู่หลัง `#` จึงไม่ถูกส่งไปเซิร์ฟเวอร์หรือบันทึกใน log; เก็บใน DB เป็น SHA-256; ส่งมากับ header `x-admin-key`; เบราว์เซอร์ที่สร้างห้องจำไว้ใน localStorage |
| สมาชิก | **participant token** (สุ่ม 144 บิต) ใน cookie แบบ `httpOnly` แยกต่อห้อง | ได้มาตอนเลือกชื่อ/พิมพ์ชื่อครั้งแรก อายุ 180 วัน |
| สมาชิก (อุปกรณ์อื่น) | **ลิงก์ส่วนตัว** `/r/{slug}#t={token}` | ผู้จัดคัดลอกส่งให้รายคนได้ หรือสมาชิกคัดลอกเองจากปุ่ม “ลิงก์ส่วนตัว” |

กันการสวมรอย:
- ชื่อในรายการที่ผู้จัดกำหนด **ถูกล็อกทันทีเมื่อมีคนเลือก** คนอื่นจะเลือกชื่อนั้นซ้ำไม่ได้ ต้องใช้ลิงก์ส่วนตัว
- ถ้ามีคนเลือกชื่อผิด ผู้จัดกด “ออกลิงก์ใหม่” เพื่อยกเลิก token เดิมและปลดล็อกชื่อ
- ถ้าต้องการความแน่นอนสูงสุด ให้ผู้จัดส่ง **ลิงก์ส่วนตัวรายคน** แทนลิงก์รวม และปิด “อนุญาตให้เพิ่มชื่อเอง”

สถานะที่ผู้จัดเห็นต่อสมาชิกแต่ละคน: **ยังไม่เปิด** → **เปิดลิงก์แล้ว** (พร้อมเวลาที่เข้าล่าสุด) → **ตอบแล้ว**
และมีปุ่ม “คัดลอกข้อความทวงคำตอบ” ที่รวมรายชื่อคนที่ยังไม่ตอบไว้ให้วางในแชต

## รูปแบบเวลา

| โหมด | ช่องต่อวัน | เหมาะกับ |
|---|---|---|
| ทั้งวัน | 1 | นัดคร่าว ๆ ช่วงยาว |
| เช้า / บ่าย / เย็น | 1–6 ช่วง (ค่าเริ่มต้น 09–12, 13–16, 17–20) | ค่าเริ่มต้น เลือกง่ายบนมือถือ — ตั้งชื่อและเวลาเองได้ต่อห้อง เช่น เช้า 08:30–12:00 |
| รายชั่วโมง | ตามช่วงที่กำหนด (ช่องละ 30/60 นาที) | ช่วงวันที่สั้น ต้องการเวลาละเอียด |

**กำหนดช่วงเวลาแยกรายวัน** (โหมดเช้า/บ่าย/เย็น และรายชั่วโมง): เปิดสวิตช์ตอนสร้างห้องหรือในแท็บ "ตั้งค่า" แล้วแตะเลือกช่วงของแต่ละวัน
เช่น วันที่ 1 เฉพาะเช้า วันที่ 2 เฉพาะบ่าย — ช่องที่ปิดแสดงเป็นลายขีดและสมาชิกเลือกไม่ได้ ถ้าปิดช่วงที่มีคำตอบอยู่แล้ว คำตอบของช่วงนั้นจะถูกลบ (ระบบเตือนก่อนบันทึก)

ผู้จัดแตะเลือกวันทีละวันบนปฏิทิน (สูงสุด 62 วัน ภายใน 1 ปี) หรือแตะชื่อวันเพื่อเลือกทั้งคอลัมน์ แต่ละช่องตอบได้ 2 ระดับ: **สะดวก** (นับ 1) และ **ถ้าจำเป็น** (นับ 0.5)
การจัดอันดับเรียงตามจำนวน “สะดวก” → “ถ้าจำเป็น” → วันที่เร็วกว่า

## ประชุมหลายวันติดกัน

ตอนสร้างห้อง (หรือแก้ภายหลังในแท็บ "ตั้งค่า") ระบุ **"ประชุมติดกันกี่วัน"** ได้ 1–14 วัน
- ชุดวันต้องเป็นวันตามปฏิทินที่ต่อเนื่องกัน และทุกวันต้องอยู่ในวันที่ผู้จัดเลือก ใช้ช่วงเวลาเดียวกันทุกวัน (ถ้ากำหนดช่วงแยกรายวัน ใช้ได้เฉพาะช่วงที่เปิดตรงกันทุกวันในชุด)
- สมาชิกยังตอบเป็นรายวันเหมือนเดิม ระบบนับคนในชุดเฉพาะคนที่ว่างครบทุกวัน — "สะดวก" ถ้าสะดวกทุกวัน, "ถ้าจำเป็น" ถ้ามีบางวันเป็นถ้าจำเป็น
- เปลี่ยนจำนวนวันได้โดยคำตอบไม่หาย; ถ้าวันประชุมที่สรุปไว้ไม่ครบชุดแล้วจะถูกยกเลิกให้อัตโนมัติ
- ไฟล์ปฏิทิน: แบบทั้งวันเป็น event เดียวคลุมทุกวัน, แบบมีเวลาเป็น event ที่ซ้ำทุกวัน N วัน (RRULE)

## สรุปและปิดรับคำตอบ

ผู้ดูแลเลือกช่วงเวลาในแท็บ "ผลรวม" แล้วกด **"สรุปและปิดรับคำตอบ"** — ยืนยันวันประชุมและล็อกคำตอบในครั้งเดียว
(หรือ "ยืนยันวันอย่างเดียว" ถ้ายังอยากรับคำตอบต่อ) จากนั้นหน้าผู้ดูแลจะมีการ์ด **"ประกาศวันประชุมให้สมาชิก"**
พร้อมข้อความสำเร็จรูป ปุ่มคัดลอก/แชร์ผ่าน LINE และปุ่ม "ยกเลิกการสรุป" เพื่อเปิดรับคำตอบอีกครั้ง
ข้อความประกาศมีลิงก์สั้น **`/r/{slug}/gcal`** สำหรับเพิ่มลง Google Calendar — redirect ไปยังวันที่สรุปล่าสุดตอนกด
จึงยังถูกต้องแม้ผู้จัดเปลี่ยนวันภายหลัง (ถ้ายังไม่สรุปจะพากลับไปหน้าห้อง)

## สมาชิกหลัก

ใส่ `*` หน้าชื่อตอนสร้างห้อง (เช่น `*ประธาน`) หรือกดดาว ★ ในแท็บ "สมาชิก" เพื่อกำหนด **สมาชิกหลัก** ที่ต้องมา
การจัดอันดับจะเอาช่วงที่สมาชิกหลัก (ที่ตอบแล้ว) ว่างครบขึ้นก่อน แล้วค่อยเรียงตามจำนวนคนว่าง
ในรายการอันดับจะบอกว่าช่วงไหนขาดใคร และเตือนก่อนสรุปถ้าช่วงที่เลือกมีสมาชิกหลักไม่ว่างหรือยังไม่ตอบ

## หมายเหตุจากสมาชิก

สมาชิกพิมพ์ "หมายเหตุถึงผู้จัด" ได้ใต้ตารางเลือกเวลา (ไม่เกิน 300 ตัวอักษร บันทึกอัตโนมัติ)
**เห็นเฉพาะผู้จัดและเจ้าของ** — ไม่อยู่ใน API สาธารณะ แสดงในแท็บ "สมาชิก" และการ์ดหมายเหตุในแท็บ "ผลรวม" ของผู้ดูแล

## วันหยุดนักขัตฤกษ์

ปฏิทินเลือกวันและหัวตารางแสดงวันหยุดเป็นสีแดงพร้อมชื่อวัน ปุ่ม "วันทำงานทั้งเดือน" ข้ามวันหยุดให้
ข้อมูลมาจากปฏิทินวันหยุดไทยสาธารณะของ Google (เฉพาะ "วันหยุดนักขัตฤกษ์" รวมวันหยุดชดเชย ไม่รวม "วันสำคัญ")
เซิร์ฟเวอร์ดึงและ cache ไว้ 12 ชม. ([src/lib/holidays.ts](src/lib/holidays.ts)) ถ้าดึงไม่ได้ใช้ข้อมูลรอบล่าสุด

## โหมดมืด

ปุ่ม **สว่าง / มืด / อัตโนมัติ** ที่ sidebar (อัตโนมัติ = ตามเครื่อง และเปลี่ยนตามทันทีถ้าเครื่องสลับธีม) จำค่าไว้ใน localStorage
สคริปต์สั้น ๆ ใน `<head>` ([src/lib/theme-init.ts](src/lib/theme-init.ts)) ตั้ง `<html data-theme>` ก่อนหน้าแสดงผล จึงไม่กะพริบเป็นสีขาว
สีหลักเป็น token ที่สลับตามธีมใน [globals.css](src/app/globals.css): `fg` (ตัวอักษร) `surface` (การ์ด) `canvas` (พื้นหลัง)
`line` (เส้นขอบ ใช้คู่กับ opacity) และ `ink` (ปุ่ม/แผงสีเข้ม และตัวอักษรบนพื้นเขียว) — โค้ดใหม่ควรใช้ token เหล่านี้แทน `text-ink`/`bg-white`/`border-black`

## Super admin (`/superadmin`)

หน้าดูแลระบบสำหรับเจ้าของเซิร์ฟเวอร์ — **ปิดอยู่จนกว่าจะตั้ง `SUPERADMIN_TOKEN`** (อย่างน้อย 24 ตัวอักษร) ใน `.env`
ไม่มีลิงก์จากหน้าใดในเว็บ และตั้ง `noindex`

| แท็บ | ทำอะไร |
|---|---|
| สถานะระบบ | จำนวนห้อง/ผู้เข้าร่วม, ฐานข้อมูล (latency, ขนาด, การเชื่อมต่อ), แอป (uptime, หน่วยความจำ), ดิสก์, ข้อมูลวันหยุด |
| ห้องทั้งหมด | ค้นหาห้อง, เปิดหน้าสมาชิก, **ออกลิงก์ผู้ดูแลใหม่** (เมื่อผู้จัดทำลิงก์หาย — ลิงก์เดิมใช้ไม่ได้ทันที), ลบห้อง |
| ล้างข้อมูลขยะ | ลบห้องที่ผ่านวันประชุมไปนานแล้ว / ห้องร้างที่ไม่มีใครตอบ — แสดงจำนวนและตัวอย่างก่อนลบ |
| ความปลอดภัย | สรุป access log ของ Traefik (เฉพาะโดเมนนี้ ย้อนหลังสูงสุด 7 วัน): IP ที่เรียกมาก, ถูก rate limit, การสแกนหาช่องโหว่, 401/403/5xx ล่าสุด + เหตุการณ์จากแอป (ลิงก์ผู้ดูแลผิด, ลิงก์ส่วนตัวผิด, ห้องเต็ม, การเข้าสู่ระบบ/ลบ/ล้างของ super admin) เก็บ 90 วัน |

**การเข้าถึง**
1. ดูรหัสบนเซิร์ฟเวอร์: `grep SUPERADMIN_TOKEN /opt/nut-prachum/.env`
2. เปิด `https://setmeet.tontaan.tech/superadmin` แล้วใส่รหัส — ได้ session 8 ชั่วโมง (cookie `HttpOnly`, `Secure`, `SameSite=Strict`)
3. ใส่ผิด 5 ครั้งต่อ IP ระงับ 15 นาที; Traefik จำกัด 60 ครั้ง/นาทีต่อ IP สำหรับ path นี้
4. เปลี่ยนรหัส (และบังคับออกจากระบบทุกเครื่อง): แก้ `SUPERADMIN_TOKEN` ใน `.env` แล้ว `docker compose up -d app`
5. ปิดหน้านี้: ลบบรรทัด `SUPERADMIN_TOKEN` แล้ว `docker compose up -d app` (ทุก path ตอบ 404)

ถ้ามี IP คงที่ จำกัดให้เข้าได้เฉพาะ IP นั้นโดยเพิ่ม label ใน `docker-compose.prod.yml`:
```yaml
traefik.http.routers.setmeet-superadmin.middlewares: setmeet-superadmin-ratelimit,setmeet-superadmin-ip
traefik.http.middlewares.setmeet-superadmin-ip.ipallowlist.sourcerange: "203.0.113.10/32"
```

## สร้างนัดซ้ำ

ปุ่ม **"สร้างนัดซ้ำ"** ที่หน้าผู้ดูแลเปิดฟอร์มสร้างห้องใหม่ (`/?repeat={slug}`) ที่เติมหัวข้อ รายละเอียด ชื่อผู้จัด
รายชื่อสมาชิกทุกคน รูปแบบเวลา จำนวนวันติดกัน และการอนุญาตเพิ่มชื่อเองไว้ให้ — ผู้จัดเลือกแค่วันและเวลาใหม่
ข้อมูลส่งผ่าน `sessionStorage` ของแท็บนั้น (ไม่ต้องเรียก API เพิ่ม) ห้องใหม่แยกจากห้องเดิม สมาชิกได้ลิงก์ส่วนตัวชุดใหม่

## ฐานข้อมูล

```
rooms                          participants                     availability
──────────────────             ──────────────────────           ─────────────────────
id            uuid PK    ◀──┐  id            uuid PK      ◀──┐  participant_id uuid FK ┐
slug          text UQ       └─ room_id       uuid FK         └─ date           date    ├ PK
title, description             name          text  (UQ ต่อห้อง)   slot           int     ┘
organizer_name                 token         text UQ             level          1 | 2
dates  date[] (วันที่เลือก)    invited       bool  (ผู้จัดเพิ่ม)
start_date, end_date (min/max)
exclude_weekends               claimed_at    (เลือกชื่อแล้ว)
required      bool (สมาชิกหลัก)
note          text (หมายเหตุถึงผู้จัด)
time_mode  day|period|hour     last_seen_at  (เปิดลิงก์ล่าสุด)
day_start_min, day_end_min     responded_at  (ตอบล่าสุด)
slot_minutes
duration_days (ประชุมติดกันกี่วัน)
date_slots jsonb (ช่วงที่เปิดรายวัน)
periods jsonb (ช่วงเวลาของห้อง, [] = ค่าเริ่มต้น)
allow_new_members, is_locked
final_date, final_slot
admin_key_hash
```

`slot` คือ index ช่วง (เรียงตามเวลาเริ่ม) ในโหมดเช้า/บ่าย/เย็น หรือ “นาทีนับจากเที่ยงคืน” ในโหมดรายชั่วโมง
`date_slots` เช่น `{"2026-11-03": [0], "2026-11-04": [1, 2]}` — วันที่ไม่อยู่ใน object เปิดทุกช่วง

| GET | `/api/rooms/:slug/me` | cookie | ฉันคือใคร (และบันทึกเวลาเข้าชม) |
| POST | `/api/rooms/:slug/me` | — | ระบุตัวตนด้วย `{token}` / `{participantId}` / `{name}` → ตั้ง cookie |
| DELETE | `/api/rooms/:slug/me` | cookie | ออกจากชื่อนี้ (“ไม่ใช่ฉัน”) |
| PUT | `/api/rooms/:slug/availability` | cookie | บันทึกช่องที่เลือกทั้งหมดของฉัน |
| GET | `/api/rooms/:slug/ics` | ทุกคน | ไฟล์ปฏิทินของวันที่สรุปแล้ว |
| GET | `/r/:slug/gcal` | ทุกคน | redirect ไป Google Calendar ของวันที่สรุปแล้ว |
| PATCH | `/api/rooms/:slug/me` | cookie | บันทึกหมายเหตุถึงผู้จัด `{note}` |
| GET | `/api/holidays` | ทุกคน | วันหยุดนักขัตฤกษ์ไทย `{ "YYYY-MM-DD": ชื่อวัน }` |
| GET / PATCH / DELETE | `/api/rooms/:slug/admin` | admin key | ดูข้อมูลผู้ดูแล / แก้ตั้งค่า, ล็อก, สรุปวัน / ลบห้อง |
| POST | `/api/rooms/:slug/admin/members` | admin key | เพิ่มรายชื่อ |
| PATCH / DELETE | `/api/rooms/:slug/admin/members/:id` | admin key | ออกลิงก์ใหม่ (`reset`), เปลี่ยนชื่อ, ตั้งสมาชิกหลัก (`required`) / ลบสมาชิก |

    ResultsPanel.tsx          ผลรวม, อันดับเวลาที่ดีที่สุด, ใครว่างช่องไหน

## ข้อควรทำเมื่อใช้งานจริง

- วางหลัง reverse proxy ที่มี HTTPS (Caddy / Nginx / Traefik) แล้วตั้ง `COOKIE_SECURE=true`
- เปลี่ยน `POSTGRES_PASSWORD` และลบ `ports` ของ service `db` ออกจาก compose
- สำรองข้อมูล volume `pgdata` ด้วย `pg_dump` เป็นระยะ

## แนวทางต่อยอด

- แจ้งเตือนผ่าน LINE Messaging API / อีเมล เมื่อสรุปวันหรือทวงคนที่ยังไม่ตอบ
- อัปเดตผลแบบ real-time ด้วย Server-Sent Events แทนการ poll ทุก 20 วินาที
- เชื่อม Google Calendar เพื่อดึงช่วงที่ไม่ว่างของสมาชิกมาแสดงอัตโนมัติ
